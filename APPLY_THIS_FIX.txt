VeriCorpus 0.1.0 — Windows Windowed EXE Fix

WHAT FAILED
-----------
The latest Windows Lite job successfully:
- installed dependencies,
- passed source checks,
- built the PyInstaller application,
- added release files.

It then failed at:
    Smoke-test packaged Windows executable

WHY
---
VeriCorpus is intentionally built as a Windows GUI application using
PyInstaller --windowed/--noconsole.

On Windows, PyInstaller sets sys.stdin/sys.stdout/sys.stderr to None in that
mode. VeriCorpus's packaged self-test (and potentially imported libraries)
can write to standard streams, which can trigger a NoneType stream error.

FIX
---
packaging/desktop_entry.py now creates harmless os.devnull-backed streams
BEFORE importing VeriCorpus if the standard streams are unavailable.

This is the workaround recommended by PyInstaller for windowed Windows apps.

A regression test simulates missing console streams.

The Windows GitHub smoke-test step also now prints desktop-selftest.json before
failing, so any future executable error is directly visible in the Actions log.

FILES
-----
packaging/desktop_entry.py
tests/test_windowed_entry.py
.github/workflows/desktop-build.yml

APPLY
-----
1. Extract this ZIP.
2. Copy its contents into your local VeriCorpus repository.
3. Replace packaging/desktop_entry.py and .github/workflows/desktop-build.yml.
4. Add tests/test_windowed_entry.py.
5. GitHub Desktop commit:
       Fix Windows windowed executable self-test
6. Push origin.
7. Actions -> Desktop bundles -> Run workflow.

The Linux Lite artifact from the previous run already built successfully, so
this patch is deliberately Windows-focused.
